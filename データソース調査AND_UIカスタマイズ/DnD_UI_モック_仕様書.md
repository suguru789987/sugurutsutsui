# Drag & Drop UI 仕様書 (会社画面・店舗画面 ダッシュボード)

## 1. 配置場所

| 画面 | 配置位置 |
|---|---|
| **会社画面** | ダッシュボード画面の「経営指標」「当月実績」セクションの下、「店舗別サマリー」「店舗ラベル別サマリー」の上 |
| **店舗画面** | ダッシュボード画面の「経営指標」「当月実績」セクションの下、「予実カレンダー」の上 |

## 3. 左パレット仕様

### タブ構成
- **全て**: ディメン+タグ+指標 一括表示（検索可）
- **ディメン**: 12-14軸（画面別）
- **タグ**: カスタムタグ6種（画面別）
- **指標**: トランザクション490/720（画面別）

### グループ表示 (折りたたみ可)
| グループ | 件数 | 配色 |
|---|---:|---|
| 📐 ディメン | 12 (会社) / 14 (店舗) | 青系 |
| 🏷️ カスタムタグ | 6 | 黄系 |
| 📊 トランザクション | 490 (会社) / 720 (店舗) | 紫系 |

### アイテム表示
- アイコン + 名称 + 制限絵文字 (🟢🟡🟠🔴)
- ホバー時にツールチップで説明
- ドラッグ可能 (HTML5 Drag and Drop API)

## 4. 中央キャンバス仕様

### ウィジェットの構成要素

| 要素 | 用途 |
|---|---|
| タイトルバー | "店舗 × 月 × 売上(税抜)" のような自動生成タイトル |
| アクションボタン | ⚙️設定 / 📋複製 / ⤢拡大 / ✕削除 |
| 本体 | クロス集計表/ヒートマップ/グラフ |

### 表示形式（チャートタイプ）

| ID | 名称 | 用途 |
|---|---|---|
| マトリクス表 | デフォルト2軸クロス | 数値詳細 |
| ヒートマップ | 時間帯×曜日 等 | パターン認識 |
| 折れ線グラフ | 時系列軸 | 推移把握 |
| 棒グラフ | 単軸×カテゴリ | 比較 |
| 円グラフ | 単軸×構成比 | シェア |
| KPIカード | 0軸（単一値） | サマリ |

### 配置とリサイズ
- グリッドレイアウト (12 columns)
- ウィジェットは1/2/3/4列幅で配置
- ドラッグ&ドロップで順序変更可能

## 5. 右設定パネル仕様

### ドロップゾーン4種

| スロット | 役割 | 受け入れる要素 | 上限 |
|---|---|---|---|
| **行 (Row)** | クロス集計の行軸 | ディメン/タグ | 1個（推奨） |
| **列 (Column)** | クロス集計の列軸 | ディメン/タグ | 1個（推奨） |
| **値 (Value)** | 集計対象 | トランザクション | 1個（推奨） |
| **フィルタ (Filter)** | 絞り込み条件 | ディメン/タグ | 複数可 |

### 制限・注意 (動的表示)
配置された要素の組合せに応じて自動表示:
- 🟢 制限なし
- 🟡 加重平均必要 / STOCK指標 / 仮値あり
- 🟠 マスタ整備が前提
- 🔴 連携必要 / 運用次第 / ブロック

例:
```
⚠️ 制限・注意
🟡 加重平均 - 率指標は加重平均(Σ分子/Σ分母)で計算
🔴 連携必要 - シフト連携必要、開発コスト=大
推奨スナップ: snap_shop_day_timeslot
```

### AIアシスト
- 自然言語入力ボックス（例: "売上が落ちている店舗を分析"）
- LLM が `主要目的_大項目/中項目` を判定 → ウィジェット推薦
- 上位3-5件を提示、クリックで自動配置

## 6. インタラクションフロー

### 新規ウィジェット作成

```
1. 左パレットから「店舗」をドラッグ
2. 右設定パネル「行」スロットへドロップ
3. 「月」を「列」へドロップ
4. 「売上(税抜)」を「値」へドロップ
5. 中央キャンバスに自動的にウィジェット生成
6. タイトル「店舗 × 月 × 売上(税抜)」自動命名
7. デフォルト表示形式（軸構成から推奨チャート選択）
8. 制限警告表示（あれば）
```

### AIアシスト経由

```
1. 右パネル「AIアシスト」に "売上低下の原因を知りたい" と入力
2. LLMが意思決定目的を分類: 売上分析→店舗別売上→売上低下要因
3. 候補ウィジェット 5件を表示
4. ユーザーがクリックで自動配置
5. 関連する補足ウィジェット (前年比、構成比等) も自動提案
```

### ビュー保存

```
1. 配置したウィジェット群を「ビュー」として保存
2. ビュー名・スコープ (個人/チーム/全社) を設定
3. 次回以降、保存ビューから1クリックで復元
```

## 8. 制限とブロック (D&D配置時)

### ハードブロック（UI上選択不可）

| パターン | 理由 |
|---|---|
| 月 × 時間帯 | スナップ粒度なし |
| 仕入先 × スタッフ | 関連性なし |
| 仕入先 × 時間帯 | 仕入は日次粒度のみ |
| 業態 × 商品 | マスタなし |
| スタッフ × 売上系 (担当者なし) | 紐付け不可 |

### ソフト警告（黄色バナー表示）

| パターン | 警告内容 |
|---|---|
| 率指標 + 集計軸 | "加重平均で計算します（Σ分子/Σ分母）" |
| 棚卸 + 日軸 | "STOCK指標は期末値、SUM不可" |
| 予算 + 実績の混在 | "確定/仮値が混在しています" |

### コスト警告

| パターン | 表示 |
|---|---|
| スタッフ × 人件費 | "🔴 シフト連携必要 (開発コスト=大)" |
| 業態関連 | "🟠 業態マスタ整備が前提" |

## 12. ビュー保存スキーマ (v3.3 拡張)

### 12.1 永続化対象

「💾 保存」操作で `savedViews[]` に push される 1 ビューの形（mock 内 `confirmSaveView()` 準拠）:

```json
{
  "id": "view_1730268000000",
  "name": "店舗別 月次売上",
  "desc": "前年比含む経営概況用",
  "savedAt": "2026-04-30 10:15",
  "screen": "company",          // 'company' | 'store' | 'both'
  "pinned": true,               // ダッシュボード固定表示
  "order": 3,                   // 表示順 (昇順=上)
  "size": "half",               // 'half' (1/2幅) | 'full' (全幅)
  "config": {
    "row":  { "id": "dim_shop",  "name": "店舗",   "type": "dim" },
    "col":  { "id": "dim_month", "name": "月",     "type": "dim" },
    "val":  { "id": "CV100",     "name": "売上(税抜)", "type": "metric" },
    "filter": [
      { "id": "dim_format", "name": "業態", "type": "dim" }
    ],
    "chart": "table",           // 'table' | 'bar' | 'line' | 'heatmap'
    "dimFilters": { "dim_format": ["居酒屋", "カフェ"] }
  }
}
```

### 12.2 フィールド詳細

| フィールド | 型 | 必須 | 用途 |
|---|---|---|---|
| `id` | string | ○ | `view_${Date.now()}` で一意 |
| `name` | string | ○ | 一覧/カード見出し |
| `desc` | string | - | 補足説明 (最大1行表示) |
| `savedAt` | string | ○ | `YYYY-MM-DD HH:mm` (ローカル) |
| `screen` | enum | ○ | 表示対象画面。`both` で会社/店舗両方に出現 |
| `pinned` | boolean | ○ | true でダッシュボードへ常駐 |
| `order` | int | ○ | 同一画面内の並び順 (1始まり) |
| `size` | enum | ○ | カードの幅 (`half` / `full`) |
| `config.row/col/val` | object\|null | - | 各ゾーンの配置要素 (id+name+type のスナップショット) |
| `config.filter` | array | - | フィルタゾーンの要素列 |
| `config.chart` | enum | ○ | 表示形式 |
| `config.dimFilters` | map | - | ディメンごとの選択メンバー (key=dim_id, value=string[]) |

### 12.3 マイグレーション

旧バージョン（v3.2 以前）で保存された `savedViews` レコードに対し、`migrateViews()` が初期化時に欠損フィールドを補完する:

| 欠損フィールド | 補完値 |
|---|---|
| `screen` | `CURRENT_SCREEN` (現在の画面) |
| `pinned` | `false` |
| `size` | `'half'` |
| `order` | 既存最大 + 1 |

`config.chart` は v3.2 から既存のため補完不要。

### 12.4 画面別フィルタリング

```js
function viewMatchesScreen(v) {
  return v.screen === CURRENT_SCREEN || v.screen === 'both';
}
```

ダッシュボード描画・設定モーダル・ピン留め一覧の全箇所で適用。これにより会社画面で店舗専用ビューが意図せず混在することを防ぐ。

## 13. ダッシュボード設定モーダル (v3.3 拡張)

### 13.1 起動

ヘッダー右の「⚙️ ダッシュボード設定」ボタン (`openDashboardConfigModal()`) で開く。
モーダル内では現在画面 (`viewMatchesScreen` 通過) のビューのみを操作対象とする。

### 13.2 操作項目（行ごと）

| カラム | 操作 | 対応フィールド |
|---|---|---|
| ▲▼ | 表示順入替 | `order` |
| 表示画面 | プルダウン (会社/店舗/両方) | `screen` |
| サイズ | プルダウン (1/2幅/全幅) | `size` |
| チャート | プルダウン (表/棒/折れ線/ヒートマップ) | `config.chart` |
| 📌固定 | チェックボックス | `pinned` |
| 🗑️ | 即時削除 (確認ダイアログ付) | `savedViews` から除去 |

### 13.3 ドラフトと反映

- 編集中の状態は `_configDraft[]` に保持し、savedViews は変更しない
- 「💾 設定を反映」 (`applyDashboardConfig()`) で `savedViews` に書き戻す
- 反映時に `order` は表示順に 1..N で正規化される

### 13.4 空状態

該当画面に表示できる保存ビューが 0 件のとき:

```
📭 この画面に表示できる保存ビューがまだありません
ビューを保存するとここに表示されます
```

### 13.5 カラーアクセント

| 画面 | 「設定を反映」ボタン色 |
|---|---|
| 会社画面 | `#10b981` (緑) |
| 店舗画面 | `#f59e0b` (オレンジ) |

## 14. 画面モード切替 (v3.4 拡張)

### 14.1 背景

v3.3 までは「ダッシュボード(保存ビュー一覧)」と「D&D 編集UI(左パレット+キャンバス+右設定)」が同一スクロール内に同居していたため、表示用途と編集用途が視覚的に分離できず情報密度が高すぎた。v3.4 で **同一HTML内のモード切替** に分離する。

### 14.2 モード

| モード | body class | 表示内容 |
|---|---|---|
| ダッシュボード (既定) | `mode-dashboard` | 経営指標 KPI / 保存ビュー一覧 (`dashboardArea`) |
| 編集 | `mode-edit` | D&D 3カラム (`dnd-section`) のみ |

### 14.3 切替手段

- ダッシュボード → 編集: ページヘッダー右の「✏️ ウィジェットを編集」ボタン
- ダッシュボード → 編集: 各保存ビューカードの「✎」(エディタで開く)、ビュー一覧モーダルの「📂 開く」(自動切替)
- 編集 → ダッシュボード: D&Dヘッダー左の「← ダッシュボードに戻る」ボタン

### 14.4 モード遷移と状態

- ビュー保存 (`💾 名前を付けて保存`) 後も**編集モードに留まる**。ダッシュボードへの自動遷移はしない（連続編集を想定）
- 編集中の `zones` / `dimFilters` / `currentChart` はモード切替で破棄されない（DOMが消えるだけで JS state は維持）
- モード切替時は `window.scrollTo({top:0})` でスクロール位置をリセット

### 14.5 空状態 (ダッシュボード)

ピン留めビューが 0 件のとき:
```
📭 まだダッシュボードに表示するビューがありません
「✏️ ウィジェットを編集」から作成→「💾 保存」で📌固定するとここに表示されます
```

### 14.6 実装API

```js
function switchMode(mode) { // 'dashboard' | 'edit'
  document.body.className = 'mode-' + mode;
  if (mode === 'dashboard') renderDashboard();
  window.scrollTo({ top: 0, behavior: 'smooth' });
}
```

CSS は body class セレクタで対象セクションを `display:none !important` に切替える宣言的方式。

## 15. ダッシュボードカードのプレビュー仕様 (v3.5 拡張)

### 15.1 レイアウト

| 項目 | 仕様 |
|---|---|
| グリッド | 1列縦積み (`grid-template-columns: 1fr`) |
| カードサイズ | 全カード均一 (`size-half`/`size-full` の差は無視) |
| 本体高さ | `min-height: 130px` / `max-height: 170px` (overflow:hidden) |

横伸び/縦伸びの不均等を解消し、ダッシュボード上は「カードが縦に並ぶ均一プレビュー」として統一。

### 15.2 クロス集計表のプレビュー切詰め

| 項目 | 仕様 |
|---|---|
| 行数 | 最大 **4行** (`rowListAll.slice(0, 4)`) |
| 列数 | データ列 **3列 + 合計1列 = 4列** (`colListAll.slice(0, 3)`) |
| ラベル文字 | 10文字超は `…` で省略 (`truncLabel(s, 10)`) |
| セル値 | `formatValue` 後にも 10文字制限を適用 |
| 合計列 | 「○○合計」→「合計」に短縮 |
| 省略行 | 末尾に「他N行 / 他N列 … エディタで全表示」案内 |

### 15.3 棒グラフのプレビュー切詰め

| 項目 | 仕様 |
|---|---|
| バー数 | 最大 **4本** |
| ラベル | 10文字制限 |
| 値表示 | 10文字制限 |
| 省略 | 末尾に「他N件 … エディタで全表示」 |

### 15.4 全表示への動線

カード右上「✎」(エディタで開く) で編集モードに自動切替し、当該ビューを `loadView()` で復元。フル表示はエディタモードでのみ可能。

## 16. ダッシュボードプレビューのソート (v3.6 拡張)

### 16.1 操作

クロス集計表プレビュー / 棒グラフプレビューの **列ヘッダー（または項目ラベル）をクリック** で昇順 → 降順 → 解除 の3段トグル。

### 16.2 ソート対象

#### クロス集計表
| ヘッダー | key | 比較ロジック |
|---|---|---|
| 行ヘッダー名 (例: 時間帯) | `row` | `naturalCompare` (数値含みは数値、それ以外は localeCompare 'ja') |
| データ列 (列メンバー) | `c0`/`c1`/`c2` | 数値比較 |
| 合計列 | `total` | 数値比較 |

#### 棒グラフ
| 操作子 | key | 比較 |
|---|---|---|
| 「項目」 | `label` | naturalCompare |
| 「(値名)」 | `value` | 数値比較 |

### 16.3 並びと切詰めの順序

ソート対象は **全データ** (slice 前)。ソート結果から先頭 4 件を表示する。これにより「上位/下位 N件」プレビューが可能。

### 16.4 値の安定化

`previewDataCache[viewId]` でランダム生成値をビュー単位にキャッシュ。再描画(=ソート操作)で値が変わらない。

### 16.5 状態保持

- ソート状態 `previewSorts[viewId] = { key, dir }` はメモリ上で保持。ページリロードで初期化（モック仕様）
- 本番では view レコードに `previewSort` フィールドとして永続化することを推奨

### 16.6 ソートアイコン

| 状態 | 表示 |
|---|---|
| 非アクティブ | ↕ (グレー) |
| 昇順 | ▲ (アクセント色) |
| 降順 | ▼ (アクセント色) |

会社=#10b981 / 店舗=#f59e0b で色分け。

## 17. 省略の明示化 (v3.7 拡張)

### 17.1 設計方針

ダッシュボードプレビューはあくまで「at-a-glance（一目で把握）」用途。スクロールで全データを見せる方向には**進めない**。代わりに以下3点で「省略していること」を視覚的に明示する。

1. **上部サマリーバー** — 表示件数 / 全件数のバッジ
2. **右端フェード + 「+N列 →」マーカー** — 横方向の見切れを示すグラデーション
3. **下部「もっと見る」リンク** — エディタへの誘導 (クリックで loadView + 編集モード切替)

### 17.2 サマリーバー

カード本体の最上部に1行の集約表示を出す。

```
📊 概要 (詳細は ✎ エディタで)            [列 4/8] [行 4/6]
```

| バッジ | 状態 | 色 (会社/店舗) |
|---|---|---|
| `列 N/M`, `行 N/M` | 省略あり (`warn`) | 黄系 (#fef3c7 / #92400e) |
| `列 N`, `行 N` | 全表示 | 緑系 / オレンジ系 |

### 17.3 列省略マーカー（セル間挿入）

省略箇所は実際の **位置（最終データ列と合計列の間）** に挟み込む。表の右端に出すと「合計の右が省略されている」と誤認されるため、明示的に列間に挿入する。

```
| 時間帯 | 月 | 火 | 水 | ⋯+4列 | 合計 |
|--------|----|----|----|-------|------|
| 21-23時|... |... |... |  ⋯   |  ... |
```

- ヘッダー: `⋯+N列` バッジ（黄色グラデーション + 破線ボーダー）
- データセル: 斜線パターン背景の `⋯` セル（クリックで `loadViewById` → エディタへ）

行省略は依然として下端フェード + 末尾「もっと見る」リンクで明示。

### 17.4 「もっと見る」誘導

末尾の最終行に（テーブル外で）クリック可能なリンクを表示:

```
💡 他2行 / 他5列 … エディタで全表示 →
```

クリックで `loadViewById(viewId)` → 編集モード切替 + ビュー復元。プレビュー上の探索動線を一切持たず、編集モードに集中させる。

### 17.5 棒グラフでも同様

| 要素 | 仕様 |
|---|---|
| サマリーバー | 「`N/M件`」バッジ + ソート操作子 |
| 下部フェード | バー数省略時 |
| もっと見るリンク | 末尾 |

### 17.6 やらないこと（決定事項）

- **カード内スクロール** は導入しない (概要思想と「✎ エディタで開く」動線が崩れるため)
- **列幅の動的調整** はしない (table-layout: fixed で均一)

## 18. 予実対比 共通メジャー (v3.8 拡張)

### 18.1 背景

「費目」ディメンションを行に置いた際、値スロットに置けるメジャーがメジャーカタログ側に存在せず、行=費目 × 値=費用 の組合せが成立しなかった（ディメンション同士は値スロットで型ガード弾き）。これを解消するため、**ディメンションに対応する予実メジャー** を共通化して追加する。

### 18.2 追加メジャー

| ID | 名称 | 種別 | フォーマット | 想定組合せ |
|---|---|---|---|---|
| `M_COST_ACT` | 費用（実績） | 金額 | `1,234,567 円` | 行=費目/店舗 |
| `M_COST_BUD` | 費用予算 | 金額 | `1,234,567 円` | 行=費目/店舗 |
| `M_COST_DIFF` | 予実差 | 金額(±) | `+12,345 円` / `-12,345 円` | 行=費目/店舗 |
| `M_COST_RATE` | 予実達成率 | % | `102.5%` | 行=費目/店舗、ベンチマーク=100% |
| `M_COST_SHARE` | 構成比 | % | `24.3%` | 行=費目（合計100%） |
| `M_COST_YOY` | 前年比 | % | `105.2%` | 任意ディメンション |

### 18.3 設計原則

- **ディメンションごとに個別メジャーを用意しない**: 「人件費の月次推移」は `行=月 × 値=費用 × フィルタ:費目=人件費` で解決
- **ただし主要費目は派生メジャーとしても残す**: `人件費 / PA人件費 / 地代家賃 / 水道光熱費` など (既存)
- 予実差・予実達成率は **同一行コンテキストで実績/予算を引き当て**: 費目ディメンションに紐づく `cost_actuals` / `cost_budgets` の差分・比

### 18.4 generateValue / formatValue 拡張

- `構成比` / `前年比` を率系判定に追加 (80–120% 範囲)
- `予実差` を独立扱い (-800,000 〜 +1,200,000 範囲、`+`プレフィックス付与)
- `費用` / `費用予算` は 2,000,000 〜 8,000,000 円 帯で生成

### 18.5 デモビュー

`view_demo3 費目別 予実達成率` を pinned で追加（会社/店舗とも）。
- 行: 費目
- 列: なし
- 値: 予実達成率
- chart: table

ダッシュボードで起動直後に「費目×予実」が見える状態。
